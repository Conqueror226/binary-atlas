# Binary Atlas contributor guidance

This is A. Kader BONZI's learning workspace and defensive research portfolio.

- Preserve existing exercises, backup schema 1, and localStorage key `binary-atlas-v1` unless implementing an explicit migration.
- Keep personal proficiency, results, versions and completion status unknown until evidence is provided. Never seed achievements.
- Edit website source in `site/`; `dist/` is generated and ignored.
- Add reviewed public reports under `portfolio/projects/` and register them in `portfolio/projects.json`.
- Keep personal browser backups out of Git. Publish reviewed material intended for the public portfolio.
- Use owned toy programs or explicitly authorized targets. State platform, architecture, ABI, flags, provenance and limits.
- Run `npm test` and `npm run build` before submitting changes. Check links with the `/binary-atlas/` base path.
- Keep local practice records separate from committed public reports. Self-verification is an author attestation, not independent validation.
- Lab scripts under `labs/<id>/` must run on the Python standard library unless the lab states otherwise, and must report missing evidence as unknown.
- EngD facts in `site/data.js` need a source. Candidate directions stay labelled as not reviewed until a supervisor or company has responded.
- Set a resource's `verified` date only after opening the page; leave it empty otherwise.
